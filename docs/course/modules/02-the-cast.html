The cast — six actors and what each one owes the others.

Every system is a small theater company. Knowing who plays which role lets you tell AI "put that logic in the engine, not the React component" and have it actually mean something.

A newsroom, not a kitchen

The "restaurant" metaphor is overused. Try this instead: a newsroom.

A risk-management report is a news story — the numbers are facts, the drift headline is the lede, the roadmap is the editorial recommendation. Each actor in the codebase has a role on that newsroom floor.

Meet the six actors

🌐

Browser SPA

The reporter — interviews the operator, captures answers, displays the finished story. React 19, lives in src/.

⚡

Vercel Edge

The newsstand — caches finished stories close to readers worldwide. 60-second cache for trends, 30-second for analysis, 1-year immutable for static.

☁️

Vercel Functions

The fact-checker — reads raw responses from the database, runs every engine, returns the story. Lives in api/. Stateless — boots fresh per request.

📦

/shared engines

The style guide — the rule book everyone consults. Question catalog, scoring formulas, signature math. Same code runs in functions AND frontend.

🐘

Supabase Postgres

The archive — every assessment, every response, every score, immutable once finalized. Two tables: assessments, responses.

🗂️

Supabase Storage

The evidence locker — PDFs and Excel sheets attached as proof, accessed via short-lived signed links. Never publicly listable.

In the codebase, who lives where?

│   └── signatures.ts
└── vercel.json     // Edge cache rules
PLAIN ENGLISH

src/ — every file the user's browser downloads. React components, screens, styling. Disposable; replace it and the data survives.

api/ — every URL that starts with /api/. These are tiny stateless servers that boot up, do one thing, return JSON, then vanish.

shared/ — the rule book. Both src/ and api/ import from here. The whole product moat lives in 600 lines of this folder.

vercel.json — tells the newsstand (Vercel Edge) how long to keep each kind of story.

Why /shared is the most important folder

Most projects have ONE place where they put "the rules" — and a duplicate of those rules in another place. Then the two copies drift apart. Bug city. We solved this by extracting the math + catalog into /shared/, then having both src/ and api/ import from it via thin re-exports. One source of truth. Engineers call this pattern "extract a kernel." Every serious software business eventually does it.
