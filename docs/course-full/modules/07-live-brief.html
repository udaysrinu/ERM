A morning newsroom briefing

An editor walks into the newsroom. They want one sentence: what's the lead story today? Then they want supporting facts. Then they want the action plan.

Today is structured the same way. The Live Brief is the lead. The pillar table is the supporting facts. The Action Plan CTA is the verb. Everything else is optional reference.

8 elements, top-to-bottom

1. Top bar BU dropdown · benchmark tabs · status pill · ⌘K palette · Report button · Back. Workspace context.
2. Live Brief hero Severity-striped card. Drift headline. 3 secondary metrics (benchmark avg / aligned pillars / active roadmap). Hero score with sparkline. Run signature chip. CTAs: Open action plan · Switch benchmark.
3. Pillar table 10 rows sorted by gap desc. Score · Bench · Δ · real per-pillar trajectory (sparkline) · status pill. Pillar names link to Provenance.
4. Pillar Shape radar 10-pillar polygon vs benchmark. Boards expect this — kept on Today after audit feedback.
5. Focus Inspector 4 dimension tiles (Governance / People / Process / Technology) vs the 4.0 "Managed" reference threshold.
6. Response coverage 4 metrics: vectors captured / evidence linked / notes captured / system integrity %. Audit-trail-friendly.
7. Pillar evolution chart Real longitudinal trend across past assessments for this BU. Powered by /api/assessments/trend.
8. Sequenced roadmap table Top 14 actions sorted by priority. Phase 1 / 2 / 3 chips. Click sort by uplift / phase / priority.

What was cut — and why subtraction is a feature

An external Devil's Advocate audit said Today had Bloomberg-cosplay levels of chart inflation. We cut 4 redundant cards in one commit:

❌

Operating Dimensions card

4 progress bars showing dimensions. Cut: Focus Inspector tiles directly above show the same data with clearer hierarchy (gap vs reference + status pill).

❌

Pillar Delta bar chart

10 vertical bars, current vs target. Cut: the pillar table's Δ column already shows score, bench, and gap side-by-side. The bar chart was the same data rendered visually.

❌

Drift Signal mini-chart

130px line of pillar deltas vs zero. Cut: the Live Brief headline says "regressed -1.00" and the pillar table has the Δ column. Three places telling the same story.

❌

Regression Alerts card

List of pillars with severity bars. Cut: the Live Brief headline IS the regression alert. The pillar table marks "Critical" rows with a coral pill. Fourth surface, same story.

✂️
Subtraction is a real engineering activity

"What can I cut?" is harder than "what should I add?" — but it's the move that makes a screen sharp. After the cuts, Today went from 13 cards to 8. Reading time dropped. Focus increased. The patent moat got more visible because it wasn't competing with 5 redundant charts.

The Live Brief headline is generated, not handwritten

CODE · src/screens/TodayScreen.tsx 
{(() => {
  const worstReg = (analysis.regressions ?? [])[0];
  if (worstReg) return (
    <>{worstReg.pillarName} regressed
    {worstReg.delta.toFixed(2)} on
    {entityName} since the prior assessment.</>
  );
  if (alignedCount >= 7) return (
    <>{entityName} is on benchmark
    across {alignedCount} of 10 pillars.</>
  );
  return (
    <>{entityName} is drifting on
    {10 - alignedCount} of 10 pillars vs ...</>
  );
})()}
PLAIN ENGLISH

Three forms, picked deterministically. No LLM. No hand-written copy. The headline is computed from the analysis JSON.

Form 1: if there's a regression, name the worst-regressed pillar and the delta. The pillar name is a clickable link to Provenance.

Form 2: if 7+ pillars are aligned, celebrate. Mint stripe.

Form 3: otherwise, "drifting" framing — names how many pillars are off-bench and which benchmark.

Why deterministic: two operators with identical analysis JSON see identical headlines. No surprise wording. Same property as the score.

A small UX win: the 2-pixel loading strip

Earlier versions blasted the whole screen with a "Computing..." overlay every time the operator switched BU or benchmark. Annoying for routine clicks.

We split loading into two states:

analysisLoading Fires on /api/assessments/[id]/analysis fetches. Shows a 2px terracotta progress strip ping-pong at the top of the screen. Non-blocking.
loading Reserved for genuinely user-blocking ops: login auth, assessment finalize. Full-screen "Computing" overlay still fires here — appropriate, because the user shouldn't keep clicking.

Lesson: not all loading is equal. Use a non-blocking indicator for routine fetches; reserve the blocking overlay for moments when blocking is the right behavior.
